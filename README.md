风控与执行——从策略到实盘的最后一公里
策略通过回测评估之后，最大的挑战才真正开始：让它在实盘环境中按纪律运行。量化交易的五层积木——数据、研究、回测、风控、执行——中风控层长期缺乏成熟的开源标准件，而这恰恰是决定长期生存能力的关键。

风控的本质是提前写死的纪律
RiskGuard 的设计宣言点出了问题的核心：风控的本质不是技术，而是提前写死的纪律。仓位上限、回撤熔断、动态仓位（Kelly 或波动率目标）和实时监控守护，这些规则必须在系统层面自动执行，因为“等你真的亏钱上头那一刻，意志力是这世界上最靠不住的东西”。

动态仓位管理的工程实现比原则复杂得多。Kelly 公式给出的是理论最优仓位，但实际应用中需要根据波动率和相关性进行缩放。Avellaneda-Stoikov 路由模型将 Kelly 资本暴露按逆波动率缩放，并根据实时库存风险进行偏斜调整。风控层的技术挑战不在于公式本身，而在于状态的持久化——回撤熔断一旦触发，即使系统重启也不能被绕过，状态必须写入不可篡改的审计日志。

执行架构的延迟分层
执行系统的延迟要求因策略类型而异，架构选择必须与策略的时间尺度匹配。对于分钟级策略，事件驱动架构配合约 300 毫秒的事件到交易延迟已经足够。对于高频策略，需要更激进的优化：将策略服务器部署在与交易柜台相同的数据中心机房，网络往返延迟可以从跨地域的几十毫秒降低到同机房的几百微秒。

GORAZD 的执行矩阵展示了极致的工程优化方向：物理绕过 Python GIL 实现确定性微秒级延迟，将 4 个 CPU 核心机械地分配给异步摄入、路由、风控和概念漂移监控四个角色，通过隔离 CPU 核心和内存映射消除操作系统页错误。对于绝大多数程序员出身的量化开发者，不需要追求这种极端延迟，但需要理解延迟分层的基本逻辑：同机房部署是性价比最高的优化手段，其次是减少网络跳数和避免不必要的序列化。

AI 推理与执行的解耦架构
2026 年的一个重要架构趋势是将“重推理”与“快执行”完全解耦。Trade in Minutes 论文描述了一种三模型架构：语义分析、数学推理和执行规划三个专用 LLM 离线将交易策略精炼为独立的可编程交易机器人，这些机器人随后被部署用于分钟级实盘交易。这种架构的价值在于：推理阶段可以充分使用大模型进行复杂分析和策略优化，执行阶段运行的是编译后的轻量级代码，不依赖模型推理的延迟和稳定性。

风控端的人机协同模式同样值得程序员参考。华泰柏瑞的实践是将持股集中度、流动性约束、业绩基准偏离度等硬性风控指标转化为系统规则，在组合调仓过程中自动校验；而异常波动、突发行业事件等需要主观判断的风险，由 AI 完成信号识别与信息解读并发出预警，最终由投研人员决策。硬规则自动执行，软判断人机协同，这条边界划分清晰且可维护。

从数据管道到因子挖掘，从统计证伪到风控执行，程序员做量化交易的技术链路已经高度成熟。AI 的价值不在于替代判断，而在于加速探索和扩展信息边界。真正决定长期收益的，仍然是那些最基础的工程纪律：数据可复现、回测不泄漏、风控不可绕过、执行按规则运行。
